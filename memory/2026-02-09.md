# 2026-02-09 - Tiny Fangs Multiplayer Bug Fix

## Bug: P2 starts with 2 mana instead of 1

**Symptom:** On the second player's first turn, they have 2 mana instead of 1.

**Root cause found in `server/GameEngine.js` ~line 1429-1438:**

```javascript
state.firstTurn = false;        // ← Set to false FIRST
// ...
if (!state.firstTurn) {         // ← This is now ALWAYS true
  nextPlayer.maxMana = Math.min(5, nextPlayer.maxMana + 1);
}
nextPlayer.mana = nextPlayer.maxMana;  // P2 incorrectly gets 2 mana
```

**Pattern:** Flag mutated before being read for the condition.

**Fix:** Save `firstTurn` value before mutating:

```javascript
const wasFirstTurn = state.firstTurn;  // Capture BEFORE mutation
state.firstTurn = false;

// ...later...
if (!wasFirstTurn) {                   // Use saved value
  nextPlayer.maxMana = Math.min(5, nextPlayer.maxMana + 1);
}
nextPlayer.mana = nextPlayer.maxMana;
```

**Status:** ✅ FIXED via subagents

## Bug 4: Animations Play Late (After KO Already Shown)

**Root cause (two-part):**
1. State updated to FINAL before animations play
2. Multiple stateUpdate messages pile up faster than animations complete

**Fix:** Added update queue system:
- `queueUpdate()` batches incoming updates
- `processUpdate()` waits for animations before applying final state
- Animations play on CURRENT state, then final state rendered

**Status:** ✅ FIXED

## Architecture Insight: Single-Player vs Multiplayer Divergence

**Single-player** (`src/effects.js`): Data-driven effects system
- Cards define effects array, engine executes them
- Adding a card = just define it

**Multiplayer server** (`server/GameEngine.js`): Hardcoded switch cases
- Each card manually translated to imperative code
- Easy to miss effects or have them drift out of sync

**Long-term fix:** Port data-driven effects system to server, or single source of truth.
